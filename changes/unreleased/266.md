The orchestrator body-file-posting verbs — `review … answer|changes|owner|ask|approve`, `ask` and `scope-review` — refuse a file whose first non-blank line is already a protocol header (`[orchestrator] …` or `[worker] …`), before any write, naming the line and the verb that adds the header itself, so a repeated `[orchestrator] ANSWER` heading can no longer reach posted comments. Worker `pr-comment` keeps its own `[worker]` de-duplication: a body already opening with a `[worker] …` line posts unchanged, a bare body gets the header added, and only a leading `[orchestrator] …` line is refused, because a worker never posts orchestrator protocol.
