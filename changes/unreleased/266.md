kind: feature

Every body-file-posting verb — `review … answer|changes|owner|ask|approve`, `ask`, `scope-review` on the orchestrator side and `pr-comment` on the worker side — now refuses a file whose first non-blank line is already a protocol header (`[orchestrator] …` or `[worker] …`), before any write, naming the line and the verb that adds the header itself. A repeated `[orchestrator] ANSWER` heading can no longer reach posted comments, and `pr-comment` now always adds the `[worker] ` header itself instead of keeping a body-prefixed header.
