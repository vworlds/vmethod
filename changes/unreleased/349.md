kind: feature

`vmethod issue parent <n> <epic>` and `vmethod issue unparent <n> <epic>` manage a configured-repository issue's epic sub-issue relation through GitHub's `addSubIssue`/`removeSubIssue`, instead of raw `gh` calls: both arguments must be in the configured repository, attaching is idempotent, and a child already parented elsewhere is refused before any write, while `issue create --parent <epic>` attaches the fresh issue after the board follow-up and names the `issue parent` retry when that attachment fails, so the created issue is never recreated.
