kind: feature

Conflict activity is now visible where people look. A step-2/3 dispatch turns the
PR card to 💥 with the fixing worker as assignee, stores the interrupted card
turn in the resolution record, restores it when the resolution resolves and hands
the PR to the orchestrator instead when it blocks; the dispatched fixer's own
comments and commits keep the conflict card. Each dispatch posts once
`[orchestrator] NOTE: resolving a conflict with <base> (step <n>, <model>)`.

The worker-status poll now drops a queued wake whose `[orchestrator]` comment is
already older than the worker's latest protocol reply, reporting
`stale wake dropped for #n` instead of restarting a worker after READY, and
`review owner` clears every queued wake for the PR. Replies the dispatched
conflict fixer posted for its resolution do not count as the task worker's
reply, so a queued wake for an unanswered ANSWER survives the fixer's own READY
and is still delivered. Conflict-fixer wakes do not use that queue and are never
dropped as stale.
