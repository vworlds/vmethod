kind: feature

`read pr` now prints the whole thread as one section per item — the PR itself (title, state, draft, head and body), then each comment, review and review comment — under stable headers naming kind, id, author with verified role and time, with bodies fenced and filtering unchanged. Every full read saves the rendered thread as `.tmp/<n>-thread.md` per checkout, beside an item id → content-hash index. `read pr --new` prints only what changed since that snapshot (new items, edited items marked `(edited)`, deleted items marked `(deleted)`) with an unchanged count, replaces the snapshot, and answers exactly `#<n>: nothing new since your last read (<k> unchanged)` when nothing changed; a missing, unreadable or corrupt snapshot falls back to the full thread under an explicit first line. The worker wake after a review answer, GO or review round points at `read pr <n> --new`, so a resumed worker reads only the new instruction instead of the entire thread each round.
