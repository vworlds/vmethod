The `Learning label` workflow checked out `pull_request.base.sha`, which
GitHub never advances while a learning PR stays open, so the job kept running
stale CLI code under the current workflow file (#309): #247's `label` job
failed with the pre-#285 token-variable error even though the workflow file on
`dev` had been updated for `GH_CONFIG_DIR` logins. The workflow now checks out
the current tip of the base branch instead, so the workflow file and the code
it runs always match and a recorded stale base cannot break labeling after a
push; it still never checks out PR head code. This checkout is a temporary
backward-compatibility fix for learning PRs opened before #285 (owner decision
2026-10-27), due for removal by 2026-11-26 to restore `base.sha`.
