kind: breaking

The following compatibility paths are **removed in this release**, with no grace period. Consumers must migrate immediately when adopting it:

- Bash-watcher consumers: stop the bash watcher, remove `legacyState` from `vmethod.yaml`, and start `vmethod watch` with fresh state; old markers, including `legacy-completed.json` / `legacy-turns.json` completion and assignment stamps, are no longer imported or migrated.
- Consumers of `legacyWorkers`, `.worktrees_` keys or `claude-workers` records: stop the old workers, remove `legacyWorkers` from `vmethod.yaml`, and re-create each open draft task's worker with `vmethod worker start <pr>`; bulk `worker adopt --from-legacy` is removed. A verified existing OpenCode session can still use explicit `worker adopt <pr> <session-id>` with the required task relation and opening Estimate.
- Consumers with a non-`opencode` worker model record: stop its old process, move the record named in the error out of `workers/`, set the card's Model to a configured OpenCode family, and run `vmethod worker start <pr>`; `models.tsv` rows must use `opencode` and full provider/model IDs (Claude uses `claude-code/<model>`), not rely on automatic conversion.
- Open PRs linked only by `Closes #n` / `Agent task for #n`: replace that header with `# Task: <title> (issue #n)` and add `<!-- vmethod-task {"issues":[n]} -->` with the actual issue number, then run `vmethod link-task <pr>` to backfill Development links; `link-task` requires an existing structured relation and does not convert legacy prose.
- Boards below v6 and issues relying on grandfathered v5 Approved moves: run `vmethod board migrate` first; obtain fresh scope approval through `vmethod scope-review <issue> <file>` and an owner Spec review → Executing move for any issue whose only approval was a historical move to Approved.
- Deliveries approved only by In review → Approved: arrange a current-head `vmethod review <pr> owner <file>` handover and a fresh owner Owner review → Approved move, or a fresh owner approval review on the current head.
- Submitters of pre-layout/non-add-only learning PRs (including the former PR 47 compatibility): reconcile the old PR, put unsubmitted delivery records in `.vmethod/model-log.jsonl`, and run `vmethod learnings submit` (with `--notes <file>` for old notes) to produce immutable files under `learnings/models/<owner>-<repo>/` and `learnings/notes/<repo>/`; old pending-layout records and flat note files are no longer read. Shipped model seed files remain readable by design.
- Boards with an `optionUpdate` / `option_update` restore journal: remove the obsolete `option_update` line from the managed README block and resume with `vmethod board migrate`; migration uses live values and never restores a saved snapshot.
- Consumers referencing the packaged `legacy/README.md`: update their links to `docs/adoption.md` and `docs/gateway.md`; `legacy/` is no longer shipped.

`checks.release` remains in the configuration schema so existing configuration files stay valid. Removed-verb documentation-test entries (`start-task`, `claude-worker`, `start-worker`) were already removed; no live verb is renamed.
