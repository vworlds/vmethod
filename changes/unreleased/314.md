kind: fix

`vmethod check` under an orchestrator environment inside the worker checkout no longer
misreports the checkout layout: the worker checkout's own repository config resolves
`workerCheckout` to itself, so `check` reports
`this is the worker checkout, but the environment is the orchestrator's (VMETHOD_ROLE=orchestrator); run check with this checkout's own .claude/settings.local.json env` instead,
and a `--online` run still names the login. A `workerCheckout` resolving into the
orchestrator's own checkout keeps the `separate clone` refusal.
