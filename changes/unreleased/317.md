Two release-step verbs close the last direct-`gh` gaps (#308): orchestrator-only
`learnings merge <pr>` squash-merges an authorized learning submission after its open,
`learning`-label, add-only validation and green-check gates, reporting the merge
commit, and `release next` dispatches the `Publish` workflow on the base branch from
a checkout at that remote head, waits for the run with a bound, and reports the
published version, npm `next` dist-tag, git tag and release URL (a red run reports
its failed step and run URL). Npm evidence polls the registry with a bound because
registry propagation can lag a correct publish; at the bound the verified git tag
and GitHub release become the authoritative version evidence with a success
warning instead of a failure.
