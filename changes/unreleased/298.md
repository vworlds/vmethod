kind: feature

`read issue` now reuses `read pr`'s thread machinery: it prints the whole issue thread as one section per item — the issue itself (title, state and body) and each comment — under the stable `### issue …`/`### comment …` headers with untrusted fences and identical filtering, and saves the same checkout-local `.tmp/<n>-thread.md` snapshot plus id → hash index. The issue item hashes its `state …` line separately from its body, so a close or reopen re-reports only the state line. `read issue --new` diffs that snapshot exactly like `read pr --new`: new comments in full, edited issue bodies marked `(edited)`, deleted items marked `(deleted)`, the unchanged count, and `#<n>: nothing new since your last read (<k> unchanged)` with exit 0 when nothing changed; a missing, unreadable or corrupt snapshot still falls back to the full thread under an explicit first line. The `issue edit` stale-read guard keeps working: every issue read refreshes the saved body hash.
